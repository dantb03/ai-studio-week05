# API키 노출 대응 절차
DB 접근 API키가 소스코드에 하드코딩되었고 github에 그대로 노출되었다.<tr>
github에 공개된 소스코드는 누구나 접근이 가능하고 크롤링이 가능하다. 
즉 전세계사람들이 DB에 접근권한이 생긴것이다.<tr>
따라서 API키를 .env파일에 격리하고 .gitignore로 .env 파일속 API키가 온라인 저장소에 유출되지 않게 고쳤다.
이번에는 가짜 API키였지만 만약 실제로 키가 노출된다면 대응절차는 다음과 같다.
1. 인지하는 즉시 해당 키를 폐기하고 새 키를 재발급받는다.
2. 새키를 .env로 격리하고 .gitignore로 트랙되지 않게 한다.(이 과정전에 커밋을 하면 안된다)
3. 사용량·청구 내역을 점검하고 필요시 사업자에 신고한다.
4. 히스토리에 남은 옛 키는 접근권한이 없으므로 남아있어도 괜찮지만, 저장소 정리가 필요하면 이력 재작성 도구를 쓴다.
